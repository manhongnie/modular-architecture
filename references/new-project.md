# 新项目开发：按需入口，不是日常默认流程

仅当任务确属从零创建项目时读取。旧项目中新增模块、路由、模型后端或测试仍走 SKILL.md 的 M1–M7。
本文件补充而不替代主文件的授权、架构、只读和验收边界。

## N1. 核对范围与现有目录

检查目标目录已有文件、适用指令、用户技术约束与当前授权范围，避免覆盖现有内容。
核对要解决的问题、用户入口、运行环境、语言、外部依赖、存储及已知资源/离线约束。
没有给出的技术选型用最小可行建议并标为假设，不默认套微服务、消息队列、数据库或固定框架。
若已有项目结构和实现，回到既有项目流程；未初始化 Git 不等于可随意创建或覆盖仓库。

## N2. 把需求整理成可验收行为

区分目标、非目标、成功与必要失败路径、已确认规则和缺口。
用户要求按流程图开发时读取 [流程图分析与开发](flowchart-development.md)，保留来源、条件和分支。
没有图时可以使用文字流程，不强制要求补图或制作图形文件。
按需求、依赖和可验收路径组织内部阶段，运行时的节点顺序不等于编码顺序。
已授权全范围实施可连续推进；只授权某阶段或有确认点时在相应边界停止。

## N3. 先设计必要骨架

给出模块职责、关键接口、主流程、扩展点、组装位置与最小文件计划。
真实变化点才抽象，节点不一一对应模块，默认不引入大型插件框架。
补充本次必要的状态所有权、失败语义、生命周期、测试与验收方式。
仅要方案时只输出方案，未经授权不创建文件。已授权实施时不逐步重复请求确认。

## N4. 实现最小可验收功能

先必要契约和主流程，再接真实实现；需要隔离外部依赖时才引入明确标记的替身。
成功路径与必需拒绝/失败路径一起完成，不因“先打通”而绕过权限、计费或数据完整性规则。
未实现入口明确禁用或报错，不用空实现、样例值、默认成功冒充生产能力。
按 SKILL.md 的架构约束隔离外部 SDK 和数据格式，集中组装，显式初始化与释放资源。

## N5. 验证并交付

复用 SKILL.md 的 M6 验证和 M7 交付要求，仅运行本范围适用且授权的检查。
有流程图时核对本阶段关键条件、边、状态与失败分支，标出代码、测试和执行证据。
区分骨架可运行、替身验证通过、真实集成通过与完整验收；前者不自动证明后者。
交付启动方法、必要配置、已完成范围、实际验证、未完成和阻断项；不擅自部署或提交。
